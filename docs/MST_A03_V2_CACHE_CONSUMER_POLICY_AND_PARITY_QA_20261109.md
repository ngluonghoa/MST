## Executed contract vs unresolved semantic gap

Real legacy `CacheIdentity` has policy dimensions beyond the existing candidate `FixturePartitionV2`: rights policy, source resolution policy, quality policy, adjustment revision, exchange/calendar, aggregation, indicator version and parameters, plus project/environment and legacy instrument mapping. **A standalone `FixturePartitionV2.digest` does not cover all these dimensions.** Changing legacy rights/indicator/quality policy can leave the V2 candidate partition digest unchanged. Reusing a manifest solely by that digest would be unsafe.

New `scripts/m2_a03_v2_cache_consumer_contract.py` defines:
- `FixtureV2ConsumerScope`: typed, explicit, synthetic-only cross-project instrument mapping (`SYN_A02_ORACLE` → `FAKE001`), exact provider, endpoint, timeframe, RAW/adjusted basis, adjustment revision namespace and session date checks. `binding_sha256` covers **all original V1 identity fields** plus the candidate partition hash and explicit instrument mapping; rejects scope drift and changed rights namespace.
- `preview_v2_consumer`: **read-only** fresh ephemeral V1 SQLite store contents and cursor; checks no bar is open or from the future; denies any historical `as_of` earlier than current last-checked cursor because V1 exposes only the latest materialized bars, not a trustworthy historical reconstructed state. Calls real V1 `full_recompute` **and separately coded Decimal EMA20/ATR14 reference oracle** against persisted checkpoints; hashes bar revision/first-known/content separately from indicator checkpoints; calls V2 `plan_fixture_refresh` for an **untrusted metadata hint**.
- Output schema `mst.a03.v2-cache-consumer-readonly-contract.synthetic.v1`: versioned full-policy binding, separate data and indicator SHA256, last observation cursor, V2 candidate partition/generation and planning hint, explicit `can_reconstruct_historical_as_of_from_latest_materialized=false`, `v2_real_drive_manifest_or_bytes_read=false`, `v2_cache_publisher_or_cas_implemented=false`, `v2_authoritative_consumer_parity_verified=false`, every entitlement/cache-write/trade/release flag false.
- `run_v2_consumer_contract_lab` **four actual stages**: cold 20 closed bars, warm reuse 20 unchanged, metadata-only revision that changes bar-revision digest but not EMA/ATR checkpoint digest, old-price revision that changes both. A rights-revoked legacy scope is denied despite the same V2 partition digest. Historical `as_of` replay from latest state also denied.

**Important limitation:** Digests generated by the untrusted caller are deterministic test fingerprints, not independent source signatures. Test V2 `FixtureHeadV2` is not an authenticated provider head or monotonic floor. A scoped read-only preview of V1's *current materialized fixture* is not a live V2 cache reader, not independently durable and cannot reconstruct time-travel source revisions.
